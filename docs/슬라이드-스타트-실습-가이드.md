# 슬라이드 & Start 노트북 제작 가이드

이 문서는 **수업 진행 방식**(슬라이드 → 실습 → 슬라이드 → 실습 반복)에 맞추어 **슬라이드 파일**과 **start 노트북**을 만드는 방법을 정리한 가이드입니다. Cursor에서 새 강의/실습을 추가할 때 참고하세요.

---

## 1. 수업 진행 방식 요약

1. **슬라이드**로 해당 섹션(예: `## 1. Google Colab 환경 확인`)을 소개한다.
2. 학생들은 **start 노트북**을 열고 그 섹션에 해당하는 부분을 **따라 실습**한다.
3. 다음 **슬라이드**(예: `## 2. Dagshub & MLflow 설정`)로 넘어가 소개한다.
4. 다시 **start 노트북**으로 돌아가 해당 섹션을 실습한다.
5. 위 과정을 **반복**한다.

따라서 **슬라이드**와 **start**는 doc(강의 문서)의 **섹션 구조(## 1, ## 2, …)** 와 1:1로 맞추어 구성하는 것이 좋습니다.

---

## 2. 디렉터리 구조

```
slides/
├── day1_1-slide-환경 설정 & MLflow 세팅.md   # 루트에 슬라이드 (Slidev 등 사용)
├── docs/                                     # 이 가이드 등 공통 문서
│   └── 슬라이드-스타트-실습-가이드.md
└── lectures/
    └── day1/
        ├── docs/
        │   └── day1_1-환경 설정 & MLflow 세팅.md   # 강의 원본 문서
        ├── complete/
        │   └── day1_1-환경설정-complete.ipynb      # 정답/완성 노트북
        └── start/
            └── day1_1-환경설정-start.ipynb        # 학생용 실습 노트북 (빈칸/수정 포인트 있음)
```

- **docs (강의 문서)**: 강의 내용의 원본. `## 1`, `## 2` 단위로 구분.
- **complete**: 모든 코드/값이 채워진 노트북. start의 기준이 됨.
- **start**: complete를 기반으로, **학생이 채워야 할 부분**만 비우고, 필요 시 **경고 문구 셀**을 넣은 버전.

## 3. 슬라이드 파일 만들기

### 3.1 파일 위치와 이름

- **위치**: 프로젝트 **루트** (예: `slides/day1_1-slide-환경 설정 & MLflow 세팅.md`).
- **이름**: `day{N}_{순서}-slide-{주제}.md` 형식을 권장.

### 3.2 프론트매터 (맨 앞)

- **테마**: `theme: ./theme-cnu` 사용.
- 샘플: `Day1-2_TF-IDF_Slides.md` 참고.

```yaml
---
theme: ./theme-cnu
background: https://cover.sli.dev
title: "Day 1-1: 환경 설정 & MLflow 세팅"
info: |
  ## 딥러닝 부트캠프 Day 1-1
  (한 줄 설명)
class: text-center
drawings:
  persist: false
transition: slide-left
mdc: true
---
```

### 3.3 페이지별 레이아웃

- **매 페이지 앞**에 Slidev 레이아웃을 명시합니다.

```markdown
---
layout: default
---

# 이 페이지 제목
내용...
```

- **자주 쓰는 레이아웃** (샘플 슬라이드 참고):
  - `default`: 일반 제목+본문
  - `center` + `class: text-center`: 제목만 크게 가운데 (섹션 구분용)
  - `two-cols-header`: 좌우 두 칸
  - `top_img-bottom_text`: 위 다이어그램/이미지, 아래 텍스트
  - `two_row_two_column`: 2x2 그리드
  - `img_caption`: 이미지+캡션

### 3.4 제목과 본문 구분 (부제처럼 보이지 않게)

- 일부 테마에서는 **`# 제목` 바로 다음에 오는 첫 줄**을 슬라이드 부제(subtitle)처럼 스타일링합니다. 본문인데 부제처럼 보이지 않게 하려면 **명시적인 소제목(`###`)을 넣어** 제목–소제목–본문 구조를 만듭니다.
- **권장 방식**: 제목 다음에 빈 줄을 두고, 본문의 첫 문장/문단이 “한 줄 요약”이나 “**굵은 문구**: 설명” 형태일 경우, 그 앞에 `### 소제목`을 넣습니다.

  ```markdown
  # 2.4 한국어: Character n-gram

  ### 한국어 교착어 문제
  "경제가", "경제는", "경제의" → TF-IDF는 모두 **다른 단어**로 취급

  ### 해결책
  `analyzer='char'` (문자 단위 분석)
  ```

- **적용 예**: 제목 아래에 “가장 먼저 … 확인합니다”, “실습 노트북에서:”, “**🔥 이 부분은 수정이 필요합니다.**” 같은 한 줄이 올 때 → `### 확인 방법`, `### 실습 노트북에서`, `### 🔥 이 부분은 수정이 필요합니다` 처럼 소제목을 두면 그 아래 내용이 본문으로만 렌더링됩니다.
- **섹션 구분 슬라이드**(`layout: center`로 제목 + 한 줄 설명만 두는 페이지)는 의도된 부제이므로 그대로 두어도 됩니다.

### 3.5 Mermaid 다이어그램 표시

- **doc에 mermaid 블록이 있으면 슬라이드에도 그대로 반영**합니다. Slidev는 mermaid를 지원하므로 코드 블록만 넣으면 렌더링됩니다.
- **표기 예시** (샘플: `Day1-2_TF-IDF_Slides.md` 참고):

  ```markdown
  ---
  layout: top_img-bottom_text
  ---
  # 제목
  ::top::
  ```mermaid
  graph LR
      A[텍스트] --> B[벡터]
      B --> C[모델]
  ```
  ::bottom::
  설명 텍스트
  ```

- **레이아웃별 활용**:
  - **top_img-bottom_text**: `::top::` 안에 mermaid 블록, `::bottom::` 안에 설명. 흐름도/개념도에 적합.
  - **img_caption**: `::img-fit-width::` 다음에 mermaid 블록. C 파라미터처럼 단일 다이어그램 + 짧은 캡션에 적합.
  - **default**: 본문 중간에 그냥 ` ```mermaid ` 블록 삽입도 가능.
- **크기 조절**: 다이어그램이 너무 크면 ` ```mermaid {scale: 0.8} ` 처럼 `{scale: 0.8}` 옵션을 붙일 수 있습니다.
- **스타일**: 노드 강조가 필요하면 mermaid 안에 `style B fill:#bbf` 같은 줄을 추가하면 됩니다.

### 3.6 내용 구성

- **doc의 `## 1`, `## 2`, …** 순서를 따라가며, 각 **##** 를 한 슬라이드 또는 몇 장으로 나눕니다.
- 한 슬라이드에 내용이 많으면 **하위 제목(###)** 단위로 잘라 여러 슬라이드로 만듭니다.
- **doc에 mermaid 다이어그램이 있을 때**는 해당 섹션 슬라이드에 같은 다이어그램을 넣어 시각적으로 보여주면 좋습니다. (위 3.5 참고)
- 슬라이드 끝에 **「실습 시작!」** 같은 문구로 “지금은 start 노트북으로 가서 이 구간 실습”을 안내하면 좋습니다.

## 4. Start 노트북 만들기

### 4.1 기본 원칙

- **complete 노트북**을 복사한 뒤, 아래만 수정해 **start**를 만듭니다.
  - **학생이 꼭 수정해야 하는 부분**만 비우기 (예: Dagshub `repo_owner`, `repo_name`).
  - **비운 단락(코드 셀) 바로 앞**에 경고용 마크다운 셀 추가.

### 4.2 비울 부분 선정

- **계정/환경에 따라 달라지는 값**: Dagshub username, repo 이름, API 키 등.
- **학생이 직접 입력해야 하는 값**: 경로, 파일명, 하이퍼파라미터 등 실습 목적상 “한 번 채워 보는” 항목.
- **그대로 두어도 되는 부분**: 라이브러리 설치, 공통 설정, 예시 코드는 complete와 동일하게 두어도 됩니다.

### 4.3 경고 셀 넣기

- 비울 **코드 셀 바로 위**에 **마크다운 셀**이 **반드시** 있어야 합니다. 그 셀에는 다음 중 하나(또는 유사한 문구)를 넣습니다:

  ```markdown
  🔥 이 부분은 수정이 필요합니다.
  ```
  또는
  ```markdown
  🔥 이 부분을 같이 작성해봅시다.
  ```

- 같은 구간에 “어떤 값을 넣으면 되는지” doc이나 슬라이드에서 이미 설명했다고 가정하고, 노트북에는 짧게만 적어도 됩니다.

### 4.3.1 비운 줄 표시 (필수)

- **비운 줄**에는 반드시 `# 🔥 직접 작성이 필요합니다.` 를 붙입니다. 한 줄 전체를 비울 때는 `변수 = # 🔥 직접 작성이 필요합니다.` 형태로 둡니다.

  ```python
  X_train, X_val, y_train, y_val = # 🔥 직접 작성이 필요합니다.
  tfidf = # 🔥 직접 작성이 필요합니다.
  y_val_pred = # 🔥 직접 작성이 필요합니다.
  ```

- 이렇게 비우면 해당 셀은 **실행 시 에러가 나는 것이 정상**입니다. 완성본은 complete 노트북에 있으므로, start에서는 "실행 가능 여부"보다 **어디를 채워야 하는지 명확히 표시**하는 데 집중합니다.

### 4.4 출력 제거

- start 노트북은 **실행 결과 없이** 배포하는 것을 권장합니다.
  - 모든 **code 셀**의 `outputs`를 비우고, `execution_count`는 `null`로 두면 됩니다.

### 4.5 제작 순서 (요약)

1. `complete/*.ipynb`를 `start/*.ipynb`로 복사.
2. 모든 code 셀의 `outputs` 제거, `execution_count` null 처리.
3. “수정 필요” 코드 셀을 찾아, 비울 줄은 `변수 = # 🔥 직접 작성이 필요합니다.` 형태로 두고, 필요한 경우 `변수 = ''` 등 플레이스홀더로 교체.
4. 그 **코드 셀 바로 앞**에 마크다운 셀을 두고, `🔥 이 부분은 수정이 필요합니다.` 또는 `🔥 이 부분을 같이 작성해봅시다.` 등으로 표시. (비운 코드 셀 앞에는 이 경고 셀이 **반드시** 있어야 함.)
5. 파일명을 `...-start.ipynb` 형태로 유지해 저장.
6. **비운 줄 때문에 셀 실행이 에러 나는 것은 허용**하며, 정답은 complete에만 두면 됨.

## 5. Doc ↔ 슬라이드 ↔ Start 매핑

| 자료 | 역할 |
|------|------|
| **doc** (`lectures/dayN/docs/...md`) | 강의 원본. `## 1`, `## 2` 단위로 구성. 슬라이드/start의 내용 근거. |
| **슬라이드** (`dayN_*-slide-*.md`) | 수업 중 보여줄 화면. doc의 ## 순서대로 한 섹션씩 소개. |
| **start** (`lectures/dayN/start/*-start.ipynb`) | 학생이 수업 중 따라 할 노트북. 같은 ## 순서로 실습 가능하도록 구성. |
| **complete** (`lectures/dayN/complete/*-complete.ipynb`) | 정답/완성본. start의 템플릿이 됨. |

- **새 강의 추가 시**: doc 먼저 작성 → complete 노트북 작성 → doc의 ##에 맞춰 슬라이드 작성 → complete에서 start 노트북 파생.

---

## 6. Cursor에서 활용 팁

- **“doc의 ## 1에 맞는 슬라이드/start 만들어줘”**처럼 **섹션 번호**를 지정하면, 해당 구간만 슬라이드/start에 반영하기 쉽습니다.
- **슬라이드 레이아웃**은 기존 샘플(`Day1-2_TF-IDF_Slides.md`)을 참고해 같은 스타일로 맞추면 일관성이 좋습니다.
- **start 노트북**을 만들 때는 “complete를 기준으로, 수정이 필요한 부분만 비우고, 그 앞에 🔥 경고 셀 추가”라고 요청하면 위 가이드와 동일한 방식으로 적용할 수 있습니다.
